# ASCII-игра в терминале "Minotaur"

## Описание

Это игра головоломка: игрок находится в лабиринте с двумя монстрами. Нам надо не попасться монстрам, найти ключ и добраться до выхода. 

Каждый монстр имеет свой характер:

1. Wonderer - если игрок подходит к нему ближе, чем на 5 клеток, он начинает охоту и находит кратчайший путь к игроку. 
2. Hunter - всегда видит, как подойти к игроку.

Если вдруг игрок и один из монстров оказались на одной клетке, либо они поменялись местами - игрок убит, и уровень начинается заново.

## Управление

Игра полностью управляется с клавиатуры. Для перемещения по лабиринту используются клавиши `W`, `A`, `S`, `D` или стрелки.

| Клавиша | Действие |
|---|---|
| `W` / `↑` | Движение вверх |
| `A` / `←` | Движение влево |
| `S` / `↓` | Движение вниз |
| `D` / `→` | Движение вправо |
| `Пробел` | Пропуск хода |
| `H` | Открыть справку |
| `Esc` | Открыть меню паузы |

Игра пошаговая. После каждого успешного хода игрока монстры получают возможность сделать свой ход.

Если игрок пытается пройти сквозь стену, его позиция не меняется, а ход не засчитывается.

Через меню паузы можно продолжить игру, сохранить текущий прогресс или вернуться в главное меню.

## Логика монстров

Выше мы уже кратко описали поведение монстров. Теперь рассмотрим подробнее, как именно они передвигаются по лабиринту и находят игрока.

В игре есть два типа монстров: **Wanderer** и **Hunter**. Оба используют алгоритм поиска в ширину (BFS) для построения кратчайшего пути до игрока, но отличаются условиями начала погони и характером передвижения.

### Wanderer

Wanderer - блуждающий монстр.

Пока игрок находится далеко, монстр передвигается случайным образом. После каждого хода игрока Wanderer выбирает одну из соседних проходимых клеток и перемещается на неё.

При случайном передвижении монстр старается не возвращаться на предыдущую клетку, если существуют другие доступные направления.

Однако когда игрок оказывается на расстоянии менее 5 шагов по лабиринту, Wanderer переходит в режим погони.

В этом режиме случайное перемещение заменяется поиском кратчайшего пути до игрока с помощью алгоритма BFS (Breadth-First Search).

**Погоня строится следующим образом:**

1. Игрок совершает ход.
2. Монстр получает текущие координаты игрока.
3. С помощью BFS находится кратчайший путь от монстра до игрока.
4. Монстр перемещается на одну клетку по найденному пути.
5. Монстр ожидает следующего хода игрока, после чего путь рассчитывается заново.

Таким образом, Wanderer может менять направление погони, если игрок начинает двигаться в другую сторону.

### Hunter

Hunter - охотник, который, в отличие от Wanderer, знает положение игрока с самого начала игры.

Ему не требуется приближаться к игроку на определённое расстояние для обнаружения цели. Он сразу начинает преследование.

Для поиска пути используется тот же алгоритм BFS, что и у Wanderer во время погони.

**Алгоритм преследования выглядит следующим образом:**

1. Игрок совершает ход.
2. Hunter определяет текущие координаты игрока.
3. При помощи BFS строится кратчайший путь.
4. В ход, когда монстру разрешено двигаться, он перемещается на одну клетку в сторону игрока.
5. При следующем перемещении путь строится заново с учётом новой позиции игрока.

Главное отличие заключается в скорости: Hunter перемещается **один раз за два хода игрока**, но при этом постоянно знает, где находится его цель.

Это делает его более предсказуемым по скорости, однако спрятаться от него за стеной или просто уйти за пределы видимости не получится.

### Столкновения

Столкновение с любым монстром приводит к смерти игрока.

Оно происходит в двух случаях:

- Игрок и монстр оказываются на одной клетке.
- Игрок и монстр одновременно меняются клетками, двигаясь навстречу друг другу.

После смерти прохождение текущего уровня начинается заново.

Каждый уровень представляет собой случайно сгенерированный лабиринт, в котором располагаются игрок, ключ, выход, монстры и бонусы.

За генерацию карты отвечают алгоритм поиска в глубину (DFS) и генератор псевдослучайных чисел.

### Генерация лабиринта

Для создания лабиринта используется алгоритм **DFS (Depth-First Search)** с возвратом назад (backtracking).

Процесс генерации выглядит следующим образом:

1. Создаётся карта заданного размера, изначально заполненная стенами.
2. Выбирается начальная клетка, которая становится проходом.
3. Алгоритм случайным образом выбирает направление движения к ещё не посещённой клетке.
4. Между текущей и выбранной клетками создаётся проход.
5. Новая клетка добавляется в стек и становится текущей.
6. Если из текущей клетки больше некуда идти, алгоритм возвращается к предыдущей клетке с помощью стека.
7. Процесс продолжается, пока не будут посещены все доступные для генерации клетки.

В результате получается лабиринт, в котором все проходы соединены между собой.

Однако у такого лабиринта есть особенность: между любыми двумя клетками существует только один маршрут.

Чтобы сделать прохождение интереснее, после основной генерации случайным образом удаляется некоторое количество внутренних стен. Это создаёт дополнительные проходы, развилки и обходные пути.

Таким образом, игрок может выбирать разные маршруты, а не двигаться по единственному возможному пути.

### Seed генерации

Генерация лабиринта использует псевдослучайные числа.

Для возможности воспроизведения одинаковых уровней предусмотрен параметр `seed`.

Если запустить генерацию несколько раз с одинаковыми параметрами и одним и тем же seed, результат будет одинаковым.

Это особенно удобно при тестировании игры и поиске ошибок в генераторе.

### Расстановка игрока, ключа и выхода

После создания лабиринта необходимо разместить игровые объекты.

Расстановка выполняется с учётом доступности клеток и расстояний между объектами.

**Игрок**

Сначала выбирается стартовая проходимая клетка, на которой появляется игрок.

Эта позиция используется как отправная точка при дальнейшей расстановке объектов.

**Выход**

Выход размещается в самой удалённой от стартовой позиции проходимой клетке.

Чтобы определить эту клетку, используется BFS, который рассчитывает длину кратчайшего пути от игрока до остальных доступных клеток.

Из полученных клеток выбирается наиболее удалённая.

Это позволяет избежать ситуаций, когда выход находится прямо рядом с игроком.

**Ключ**

Ключ размещается на свободной проходимой клетке лабиринта.

При размещении необходимо убедиться, что игрок может добраться до него и что выбранная клетка не занята другим объектом.

Сам по себе выход закрыт. Для завершения уровня игрок должен сначала найти ключ, а затем добраться до выхода.

### Расстановка монстров

Монстры размещаются после генерации карты с учётом стартовой позиции игрока.

При расстановке соблюдаются следующие условия:

1. Монстр должен находиться на проходимой клетке.
2. Клетка не должна быть занята другим игровым объектом.
3. Расстояние от стартовой позиции игрока до монстра должно составлять не менее 6 шагов по лабиринту.

Расстояния проверяются при помощи BFS, чтобы учитывался именно путь по коридорам, а не расстояние по прямой.

Это необходимо для того, чтобы игрок не погибал сразу после начала уровня.

### Проверка корректности карты

После генерации и расстановки объектов карта проверяется на корректность.

В частности, необходимо убедиться, что:

- На карте присутствуют игрок, ключ и выход.
- Ключ доступен из стартовой позиции игрока.
- До выхода существует проходимый путь.
- Все объекты размещены в допустимых клетках.
- Монстры находятся на достаточном расстоянии от игрока.

Если карту невозможно корректно заполнить объектами, генерация считается неудачной и об этом сообщается через исключение.

### Увеличение сложности

Всего в игре предусмотрено 7 уровней.

С каждым следующим уровнем увеличиваются размеры лабиринта и количество монстров. Также параметры уровня определяют количество бонусов.

Из-за этого поиск ключа и выхода становится сложнее, а вероятность встретить монстра возрастает.

После прохождения седьмого уровня игрок побеждает.
