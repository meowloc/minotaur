# Генерация лабиринта: разбор текущей реализации

Это руководство описывает **уже написанные** функции генерации карты: создание
матрицы стен, расстановку игрока и выхода, а затем прокладку первого пути через
лабиринт. Файл предназначен для разработчика и для подготовки к защите проекта.
Полная генерация игрового уровня (ключ, монстры, бонусы, дополнительные обходные
пути) **пока не реализована** в рассматриваемом коде.

## Какие файлы за что отвечают

| Файл | Назначение |
| --- | --- |
| `minotaur/constants.py` | Размеры уровней `LEVEL_SIZES` и обозначения клеток: `FILE_WALL`, `FILE_AIR`, `PLAYER`, `EXIT`. |
| `minotaur/generator.py` | `init_map_gen` создаёт карту из стен; `making_labyrinth` прокладывает путь с помощью DFS. |
| `minotaur/levels.py` | `place_exit_and_player` выбирает стартовую позицию и выход. |
| `minotaur/exceptions.py` | `GenerationError` — ошибки генерации; `PlaceError` — ошибки расстановки. |
| `tests/test_generation.py` | Шесть тестов создания карты, расстановки, DFS и обработки неверных данных. |

Координаты в коде задаются парой `(row, col)`: сначала номер строки (сверху
вниз), затем номер столбца (слева направо). Карта — список строк, причём
каждая строка сама является списком односимвольных обозначений клеток.

## Общий порядок вызовов

1. `init_map_gen(level_num)` — создаём прямоугольную матрицу, целиком
   заполненную стенами.
2. `place_exit_and_player(map_matrix, rng)` — выбираем выход и наиболее
   удалённую от него стартовую клетку игрока, записываем их в матрицу.
3. `making_labyrinth(map_matrix, rng)` — ищем игрока и выход, затем DFS
   прорубает проходы от игрока к выходу.
4. Полученную матрицу можно передавать следующему этапу разработки уровня.
   Создание ключа, монстров и других объектов здесь пока отсутствует.

Порядок важен: функция расстановки принимает **только карту из стен**, а DFS
требует, чтобы на карте **уже были игрок и выход**. Обе функции изменяют
полученную матрицу на месте, а не создают новую.

## Разбор функций

### `init_map_gen(level_num)` — `minotaur/generator.py`

Принимает **индекс уровня с нуля**. По `constants.LEVEL_SIZES[level_num]`
получает `(height, width)` и создаёт `height` независимых списков длиной
`width`. Каждая клетка имеет значение `constants.FILE_WALL` (`#`).

Перед созданием проверяет, что индекс — целое число, находится в диапазоне
существующих уровней, а оба размера — целые числа не меньше пяти. В случае
ошибки выбрасывает `GenerationError`.

Например, карта размером 5 × 5 сразу после инициализации выглядит так:

```text
#####
#####
#####
#####
#####
```

### `place_exit_and_player(map_matrix, rng=None)` — `minotaur/levels.py`

Сначала проверяет, что у карты не меньше пяти строк и столбцов, все строки
одинаковой длины, а все клетки — стены. Нарушение этих условий приводит к
`PlaceError`.

Далее алгоритм:

1. Находит допустимые клетки с **нечётными координатами**, расположенные
   у внутренней стороны границы лабиринта.
2. Случайно выбирает среди них положение выхода `E`.
3. Для каждой допустимой клетки вычисляет **манхэттенское расстояние** до
   выхода: `abs(row - exit_row) + abs(col - exit_col)`.
4. Находит максимальное такое расстояние. Если несколько клеток одинаково
   удалены, выбирает одну из них случайно для игрока `P`.
5. Помещает символы `P` и `E` в исходную матрицу и возвращает пару
   координат `(player, exit_pos)`.

Переменная `max_distance = -1` означает «максимум пока не найден»: реальные
манхэттенские расстояния неотрицательны, поэтому первая проверенная клетка
обязательно обновит максимум. Список `farthest_cells` нужен для случайного
выбора при равенстве расстояний.

**Важно:** здесь используется расстояние по строкам и столбцам, *не*
длина пути по коридорам (коридоров на этом этапе ещё нет). Выход и игрок
размещаются до запуска DFS.

### `making_labyrinth(map_matrix, rng=None)` — `minotaur/generator.py`

Находит в матрице `P` (игрока) и `E` (выход). Если хотя бы одного из них нет,
выбрасывает `GenerationError`. Затем использует **обход в глубину — DFS
(Depth-First Search)** — со стеком и возвратом назад (backtracking).

1. Кладёт координаты игрока в `stack` и `visited`.
2. Из текущей клетки рассматривает направления вверх, вниз, влево и вправо
   с шагом **в две клетки**.
3. Отбрасывает позиции за внутренней границей карты и уже посещённые клетки.
4. Если есть варианты, случайно выбирает следующий, удаляет стену **между**
   текущей и следующей клетками, открывает следующую клетку (если это не `E`),
   заносит её в `visited` и `stack`.
5. Если вариантов больше нет — удаляет вершину стека и возвращается назад.
6. Когда вершина стека совпадает с координатами выхода, возвращает матрицу.
   Если стек опустел раньше, выбрасывает `GenerationError`.

Проход обозначается `constants.FILE_AIR` (`.`). Стена `#` между двумя
клетками удаляется через средние координаты. Шаг в две клетки позволяет
оставлять промежуточные стенки и управляемо открывать проходы. Исходные
обозначения игрока `P` и выхода `E` сохраняются.

Алгоритм **останавливается сразу после достижения выхода**, а не после
посещения всего поля. Поэтому это именно первый проложенный путь, а не
финальная реализация всего лабиринта. Исследованные до выхода ответвления
тоже остаются открытыми проходами.

Пример из теста, где перед DFS игрок стоит в `(1, 1)`, а выход — в `(3, 3)`:

```text
До DFS:     После DFS:
#####       #####
#P###       #P..#
#####       ###.#
###E#       ###E#
#####       #####
```

## Как получить воспроизводимую карту

Обе функции, в которых есть случайный выбор, принимают необязательный
аргумент `rng` (`random.Random`). Если не передать его, создаётся собственный
генератор случайных чисел. Если передать генератор с определённым seed,
результат последовательных вызовов можно повторить.

Ниже — **пример использования после объединения кода генерации с константами
из `dev`**:

```python
import random

from minotaur.generator import init_map_gen, making_labyrinth
from minotaur.levels import place_exit_and_player

rng = random.Random(0)
maze = init_map_gen(0)
player, exit_pos = place_exit_and_player(maze, rng)
making_labyrinth(maze, rng)

print("Игрок:", player, "Выход:", exit_pos)
for row in maze:
    print("".join(row))
```

В этом примере `maze` остаётся одним и тем же объектом на всех этапах.
Для повтора результата нужно заново создать `random.Random(0)` и новую
матрицу.

## Ошибки и тестирование

- `GenerationError` (`minotaur/exceptions.py`) — неверный номер или размер
  уровня, отсутствие игрока/выхода, невозможность найти путь.
- `PlaceError` (`minotaur/exceptions.py`) — слишком маленькая, неровная или
  уже заполненная чем-то кроме стен карта перед расстановкой.

Тесты находятся в `tests/test_generation.py`. Они проверяют корректное
создание карты, ошибку индекса уровня, расстановку при фиксированном seed,
отказ от размещения на занятой карте, путь DFS при фиксированном seed и
отсутствие игрока/выхода:

```bash
python -m pytest tests/test_generation.py
```

**Особенность веток:** `feature/init_map_generation` начинается от второго
merge-коммита, когда `minotaur/constants.py` ещё был пустым. Необходимые
константы находятся в `dev` после третьего merge. Поэтому запуск примера и
полный прогон тестов возможны **после объединения соответствующих изменений**;
изолированная ветка генерации пока не является самостоятельно запускаемой.
Это зависимость между ветками, а не ошибка в командах выше.

## Что ещё не сделано

Текущие три функции не расставляют ключи, монстров и бонусы; не создают
дополнительные обходные пути и не выполняют итоговую проверку проходимости
всех игровых объектов. Не следует описывать эти функции как полностью
готовую систему генерации уровней: перечисленное — следующие этапы проекта.
