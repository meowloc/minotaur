# Генерация лабиринта: разбор текущей реализации

Это руководство описывает **уже написанные** функции генерации карты: создание
матрицы стен, расстановку игрока и выхода, прокладку первого пути через
лабиринт и открытие дополнительных проходов. Файл предназначен для разработчика
и для подготовки к защите проекта. Расстановка ключа, монстров и бонусов
**пока не реализована** в рассматриваемом коде.

Руководство описывает код из `feature/add-loops`, включая ранее добавленные
в `dev` функции. Ветка `feature/make-readme` хранит документацию и сама по себе
пока не содержит этот код. Примеры и тесты ниже запускаются из корня
`feature/add-loops` либо ветки, в которую уже вошли эти изменения.

## Какие файлы за что отвечают

| Файл | Назначение |
| --- | --- |
| `minotaur/constants.py` | Размеры `LEVEL_SIZES`, число дополнительных проходов `LEVEL_CONTENTS[level_num][3]` и обозначения клеток. |
| `minotaur/generator.py` | `init_map_gen` создаёт карту из стен; `making_labyrinth` прокладывает путь с помощью DFS; `add_loops` открывает стены между существующими коридорами. |
| `minotaur/levels.py` | `place_exit_and_player` выбирает стартовую позицию и выход. |
| `minotaur/custom_types.py` | `Cell` хранит координаты клетки с полями `row` и `col`. |
| `minotaur/exceptions.py` | `GenerationError` — ошибки начальной генерации; `PlaceError` — ошибки расстановки; `LevelError` — ошибки в `add_loops`. |
| `tests/test_generation.py` | Четырнадцать тестов создания карты, расстановки, DFS, дополнительных проходов и обработки неверных данных. |

Координаты в коде задаются через `Cell(row, col)`: сначала номер строки (сверху
вниз), затем номер столбца (слева направо). Нумерация начинается с нуля.
Карта — список строк, причём
каждая строка сама является списком односимвольных обозначений клеток.

## Общий порядок вызовов

1. `init_map_gen(level_num)` — создаём прямоугольную матрицу, целиком
   заполненную стенами.
2. `place_exit_and_player(map_matrix, rng)` — выбираем выход и наиболее
   удалённую от него стартовую клетку игрока, записываем их в матрицу.
3. `making_labyrinth(map_matrix, rng)` — ищем игрока и выход, затем DFS
   прорубает проходы от игрока к выходу.
4. `add_loops(map_matrix, count, rng)` — открываем ровно `count` стен между
   существующими коридорами. Для уровня число берётся из
   `constants.LEVEL_CONTENTS[level_num][3]`.
5. Полученную матрицу можно передавать следующему этапу разработки уровня.
   Создание ключа, монстров и других объектов здесь пока отсутствует.

Порядок важен: функция расстановки принимает **только карту из стен**, а DFS
требует, чтобы на карте **уже были игрок и выход**. `add_loops` вызывается
после DFS на связной карте. Все три функции после `init_map_gen` изменяют
полученную матрицу на месте, а не создают новую. Если подходящих стен для
`count` не хватает, `add_loops` сообщает об ошибке, не меняя карту.

## Разбор функций

### `init_map_gen(level_num)` — `minotaur/generator.py`

Принимает **индекс уровня с нуля**. По `constants.LEVEL_SIZES[level_num]`
получает `(height, width)` и создаёт `height` независимых списков длиной
`width`. Каждая клетка имеет значение `constants.FILE_WALL` (`#`).

Перед созданием проверяет, что индекс — целое число, находится в диапазоне
существующих уровней, а оба размера — целые числа не меньше пяти. В случае
ошибки выбрасывает `GenerationError`.

Например, карта размером 5 × 5 сразу после инициализации выглядит так:

```text
#####
#####
#####
#####
#####
```

### `place_exit_and_player(map_matrix, rng=None)` — `minotaur/levels.py`

Сначала проверяет, что у карты не меньше пяти строк и столбцов, все строки
одинаковой длины, а все клетки — стены. Нарушение этих условий приводит к
`PlaceError`.

Далее алгоритм:

1. Находит допустимые клетки с **нечётными координатами**, расположенные
   у внутренней стороны границы лабиринта.
2. Случайно выбирает среди них положение выхода `E`.
3. Для каждой допустимой клетки вычисляет **манхэттенское расстояние** до
   выхода: `abs(row - exit_row) + abs(col - exit_col)`.
4. Находит максимальное такое расстояние. Если несколько клеток одинаково
   удалены, выбирает одну из них случайно для игрока `P`.
5. Помещает символы `P` и `E` в исходную матрицу и возвращает пару
   координат `(player, exit_pos)`, каждая из которых имеет тип `Cell`.

Переменная `max_distance = -1` означает «максимум пока не найден»: реальные
манхэттенские расстояния неотрицательны, поэтому первая проверенная клетка
обязательно обновит максимум. Список `farthest_cells` нужен для случайного
выбора при равенстве расстояний.

**Важно:** здесь используется расстояние по строкам и столбцам, *не*
длина пути по коридорам (коридоров на этом этапе ещё нет). Выход и игрок
размещаются до запуска DFS.

### `making_labyrinth(map_matrix, rng=None)` — `minotaur/generator.py`

Находит в матрице `P` (игрока) и `E` (выход). Если хотя бы одного из них нет,
выбрасывает `GenerationError`. Затем использует **обход в глубину — DFS
(Depth-First Search)** — со стеком и возвратом назад (backtracking).

1. Кладёт координаты игрока в `stack` и `visited`.
2. Из текущей клетки рассматривает направления вверх, вниз, влево и вправо
   с шагом **в две клетки**.
3. Отбрасывает позиции за внутренней границей карты и уже посещённые клетки.
4. Если есть варианты, случайно выбирает следующий, удаляет стену **между**
   текущей и следующей клетками, открывает следующую клетку (если это не `E`),
   заносит её в `visited` и `stack`.
5. Если вариантов больше нет — удаляет вершину стека и возвращается назад.
6. Когда вершина стека совпадает с координатами выхода, возвращает матрицу.
   Если стек опустел раньше, выбрасывает `GenerationError`.

Проход обозначается `constants.FILE_AIR` (`.`). Стена `#` между двумя
клетками удаляется через средние координаты. Шаг в две клетки позволяет
оставлять промежуточные стенки и управляемо открывать проходы. Исходные
обозначения игрока `P` и выхода `E` сохраняются.

Алгоритм **останавливается сразу после достижения выхода**, а не после
посещения всего поля. Поэтому это именно первый проложенный путь, а не
финальная реализация всего лабиринта. Исследованные до выхода ответвления
тоже остаются открытыми проходами.

Пример из теста, где перед DFS игрок стоит в `(1, 1)`, а выход — в `(3, 3)`:

```text
До DFS:     После DFS:
#####       #####
#P###       #P..#
#####       ###.#
###E#       ###E#
#####       #####
```

### `add_loops(map_matrix, count, rng=None)` — `minotaur/generator.py`

Обходим внутренние клетки карты, проверяем, что это стена и одна её координата
чётная, а другая нечётная. Затем проверяем проходы с двух сторон: слева и справа
либо сверху и снизу, в зависимости от положения стены. Если с обеих сторон
не стены, добавляем клетку в кандидаты на удаление. После обхода случайно
выбираем `count` разных кандидатов и заменяем стены воздухом. Если кандидатов
не хватает — выдаём `LevelError`, карту не меняем.

Здесь «перегородка» означает обычную стену `#` между двумя существующими
проходами. Отдельного типа клеток для неё нет. На связной карте между этими
проходами уже можно добраться другим маршрутом. Открытие стены добавляет
ещё одно соединение, поэтому появляется обход.

#### Зачем проверять чётность координат

Игрок и выход размещаются на нечётных координатах. DFS от игрока делает шаги
по две клетки: `1 → 3 → 5 → 7`. При каждом шаге он открывает и выбранную
клетку, и стену посередине. Поэтому координаты позволяют определить, какие
клетки разделяет стена:

- Стена `(3, 2)` находится между `(3, 1)` и `(3, 3)`. Строка нечётная,
  столбец чётный — проверяем слева и справа.
- Стена `(2, 7)` находится между `(1, 7)` и `(3, 7)`. Строка чётная,
  столбец нечётный — проверяем сверху и снизу.

Клетки с обеими нечётными координатами — места, куда DFS может сделать шаг.
Они уже открыты либо остались стенами, если DFS до них не дошёл. `add_loops`
не открывает эти клетки. Клетки с обеими чётными координатами не лежат
посередине горизонтального или вертикального шага DFS, их тоже пропускаем.
Чётность определяет положение клетки в сетке, а не то, стена в ней или воздух.

#### Последовательность действий в функции

1. Проверяем, что `count` — целое неотрицательное число, размеры карты
   не меньше 5 × 5, а строки одинаковой длины. Иначе возникает `LevelError`.
2. Если `count == 0`, сразу возвращаем карту без изменений.
3. Если `rng` не передан, создаём `random.Random()`.
4. Создаём пустой список `walls`. Вложенными циклами перебираем все внутренние
   клетки с шагом один. Внешние строки и столбцы не рассматриваем.
5. Пропускаем клетки, которые не являются стенами. Проверкой чётности
   определяем положение стены и выбираем пару противоположных соседей.
6. В `first` и `second` записываем символы соседей. Если оба символа не `#`,
   добавляем координату стены `Cell(row, col)` в `walls`. Клетки игрока
   и выхода тоже считаются проходимыми.
7. Если `count > len(walls)`, выбрасываем `LevelError`. До этой проверки
   карта ещё не изменялась.
8. Повторяем `count` раз: `rng.choice(walls)` выбирает стену, заменяем её
   на `FILE_AIR`, затем `walls.remove(wall)` убирает координату из списка.
   Благодаря удалению каждый раз выбирается новая стена.
9. Возвращаем ту же матрицу. Стен стало меньше ровно на `count`; игрок,
   выход и все прежние проходы остались на своих местах.

Это не повторный DFS: здесь нет стека, возврата назад и достраивания коридоров.
Функция рассчитана на связную карту после `making_labyrinth`, но сама полную
проверку связности не выполняет. Поскольку DFS останавливается у выхода,
подходящих стен может оказаться мало или вообще не быть. В таком случае
возникает `LevelError`, а не открытие меньшего числа стен или повторная генерация.

#### Пример на карте из текущего генератора

Для первого уровня (`level_num=0`) и общего `random.Random(2)` последовательность
вызовов из примера ниже даёт следующую карту. Слева результат `making_labyrinth`,
справа — после `add_loops` с `count=2`:

```text
До:                После:
    012345678          012345678
  0 #########        0 #########
  1 #E#.....#        1 #E#.....#
  2 #.#.#.###        2 #.#.#.###
  3 #.#.#...#        3 #.......#
  4 #.#.###.#        4 #.#.###.#
  5 #...###P#        5 #...###P#
  6 #########        6 #########
```

При обходе слева направо и сверху вниз получаем кандидатов:
`Cell(1, 2)`, `Cell(2, 7)`, `Cell(3, 2)`, `Cell(3, 4)`.
Например, у стены `(1, 2)` слева выход `E`, справа проход `.`, поэтому она
подходит. У стены `(4, 5)` сверху проход, а снизу ещё стена, поэтому её
не добавляем. В этом запуске случайный выбор открывает `(3, 2)` и `(3, 4)`.
Остальные клетки не меняются. Через третью строку теперь можно пройти прямо,
а старые маршруты через верх и низ карты сохраняются.

## Как получить воспроизводимую карту

Все три функции, в которых есть случайный выбор, принимают необязательный
аргумент `rng` (`random.Random`). Если не передать его, создаётся собственный
генератор случайных чисел. Если передать генератор с определённым seed,
результат последовательных вызовов можно повторить.

Ниже — пример для `feature/add-loops` либо ветки с этим кодом:

```python
import random

from minotaur import constants
from minotaur.generator import add_loops, init_map_gen, making_labyrinth
from minotaur.levels import place_exit_and_player

rng = random.Random(2)
level_num = 0
maze = init_map_gen(level_num)
player, exit_pos = place_exit_and_player(maze, rng)
making_labyrinth(maze, rng)
add_loops(maze, constants.LEVEL_CONTENTS[level_num][3], rng)

print("Игрок:", player, "Выход:", exit_pos)
for row in maze:
    print("".join(row))
```

В этом примере `maze` остаётся одним и тем же объектом на всех этапах.
Для повтора результата нужно заново создать `random.Random(2)` и новую
матрицу, затем выполнить те же вызовы в том же порядке. Один и тот же `rng`
передаётся в расстановку, DFS и открытие дополнительных проходов.
Для другого seed подходящих стен может не хватить; вызывающему коду нужно
обработать `LevelError`. Пример с seed=2 успешно открывает две стены.

## Ошибки и тестирование

- `GenerationError` (`minotaur/exceptions.py`) — неверный номер или размер
  уровня, отсутствие игрока/выхода, невозможность найти путь.
- `PlaceError` (`minotaur/exceptions.py`) — слишком маленькая, неровная или
  уже заполненная чем-то кроме стен карта перед расстановкой.
- `LevelError` (`minotaur/exceptions.py`) — неверный `count`, слишком маленькая
  или неровная карта, нехватка подходящих стен в `add_loops`.

Тесты находятся в `tests/test_generation.py`. Они проверяют корректное
создание карты, ошибку индекса уровня, расстановку при фиксированном seed,
отказ от размещения на занятой карте, путь DFS при фиксированном seed и
отсутствие игрока/выхода. Восемь новых тестов `add_loops` проверяют:

- Открытие стены между верхним и нижним проходами.
- Открытие стены между левым и правым проходами.
- Возврат карты без изменений при `count=0`.
- Открытие ровно заданного числа разных стен и повторяемость по seed.
- Ошибку при нехватке кандидатов без изменения карты.
- Отсутствие достраивания карты после старого DFS.
- Ошибку при отрицательном, дробном, строковом или логическом `count`.
- Ошибку при пустой карте или строках разной длины.

Запуск проверок из корня ветки с реализацией:

```bash
python -m pytest tests/test_generation.py
python -m pytest
python -m flake8 main.py minotaur tests
```

## Что ещё не сделано

Текущие четыре функции не расставляют ключи, монстров и бонусы и не выполняют
итоговую проверку проходимости всех игровых объектов. Дополнительные обходы
реализованы через `add_loops`, но успешное открытие заданного числа стен
не гарантируется для любого результата первого DFS. Полная генерация игрового
уровня остаётся следующим этапом проекта.
